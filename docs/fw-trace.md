# FW 总模块·诊断副本

独立 ID `hyj1817.fw.trace`，基于现有总模块生成；不修改原总模块、网站解析逻辑或正式订阅清单。

## 设计与实现计划

1. 新建 `scripts/fw-trace-runtime.js`：入口及请求前后记录脱敏阶段、耗时、状态码、字段存在性。独立缓存只保留最近 60 条事件；写日志失败不打断原调用。网站数据缓存在副本内禁用，确保测试触发请求；不读取或覆盖原版缓存。
2. 新建 `scripts/build-fw-trace.js`：读取现有 `widgets/fw-all.js`，修改副本元数据，注入每个站点命名空间的 HTTP 代理和日志函数，并包装公开入口。输出独立 `widgets/fw-trace.js`。
3. 新建 `tests/fw-trace.test.js`：先运行失败，再实现；模拟 HTTP 检查参数和返回值不变、请求失败和挂起可观察、无定时器可运行、跨上下文读取、日志脱敏及原版字节不变。
4. 执行诊断测试和原版 `npm run verify`，仅发布新文件，取回远程文件比较。

## 使用

1. 导入 `widgets/fw-trace.js`，保留原版，不需要替换。
2. 在 **FW 总模块·诊断副本 → 诊断：开始新记录 → 测试** 开始记录。
3. 从这个副本的 `[诊断]` 首页模块进入，重试一次失败操作；不要从原版首页测试。
4. 返回副本，打开 **诊断：读取记录 → 测试**，复制 `FW_TRACE` 日志。

诊断入口返回空列表为正常行为。它不会返回假的播放线路，原函数的正常结果原样返回。副本会进行与原模块逻辑相同的网络请求，未增加探测网站、绕过验证或解析规则。

## 日志解释与限制

`entry-start/end/error` 表示入口开始、结束、异常；`http-start/end/error` 表示实际请求阶段。只有开始没有结束可能是尚未返回，也可能是宿主提前终止脚本，不能单凭这一条断言服务器故障。原代码自己捕获的异常会记录为 `source-note`，不输出原始消息。

记录只包含固定字段的存在性、类型、已知站点前缀标签，以及状态码、耗时、数量。不会保存原始 ID、标题、URL、HTTP 头、令牌、响应正文或异常文本。**Forward 自己的 debug 日志仍可能显示请求地址和请求头；发送前请只复制 `FW_TRACE` 行，或遮盖凭据。**

不同 JS 上下文通过独立命名空间交换最近记录；没有持久缓存时仅当前上下文可用，读取页会提示。事件时间及随机事件 ID 用于识别重复或历史调用，但不是跨所有异步请求的完整链路追踪。

验证命令：`node scripts/build-fw-trace.js`、`node tests/fw-trace.test.js`、`npm run verify`。本地验证只使用虚构地址和模拟响应，不访问真实站点。
