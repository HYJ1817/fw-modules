# FW 独立诊断

独立 ID `hyj1817.fw.diagnostics`，版本 1.0.0。它可以与 FW 总模块共存，不替换或修改总模块，也不添加到正式订阅清单。

## 操作

1. 通过单独的 `widgets/fw-diagnostics.js` Raw 链接导入。
2. 打开 **FW 独立诊断 → 1. 环境自检 → 测试**，保留运行日志。
3. 返回原来的 FW 首页，重试一次加载失败的操作。
4. 打开 **FW 独立诊断 → 2. 读取最近调用记录 → 测试**，复制运行日志。

三个入口均返回空列表，这是设计行为，不代表诊断失败。结果在 `FW_DIAG` 日志中。不要把“诊断监听”的模拟测试当作实际调用；默认媒体 ID 会标记为 `builtinTest: true`。请核对报告时间，旧报告不会因为打开读取入口而清除。

## 能判断什么

- 独立模块运行时是否提供定时器及原生 HTTP API。
- 独立模块的缓存是否能写入再读回。
- 若 Forward 调用了独立诊断播放源，它收到的固定字段是否存在、数据类型是什么。

## 限制与隐私

此模块不访问网站，不请求或返回视频，不读取其他模块缓存，不捕获其他模块内部的请求状态，也不能保证 Forward 一定调用它。`NO_CAPTURE` 可能是未调用、未启用、缓存不可用，不等于 FW 总模块没运行。`memory-only` 表示只在当前 JS 上下文保留记录，跨测试可能丢失。

只保留最近一次调用的时间、字段存在性和类型。不记录影片名称、ID 值、完整网址、Cookie、令牌或原始异常文本。所有写入使用独立命名空间。排查结束后可停用或移除此模块；它不影响原模块文件。

开发验证：`node tests/fw-diagnostics.test.js`；该测试不访问网络。
